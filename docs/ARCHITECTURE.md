## Runtime and data flow

The [production runtime diagram](../README.md#production-runtime) shows the public ingress, application services, data stores, and mail provider.

1. Nginx terminates HTTPS, serves the built React application with a client-route fallback, and proxies `/api/` and `/health` to FastAPI. The production configuration also forwards signed object requests under `/portal-files/`. [Production Nginx configuration](../nginx/nginx.prod.conf)
2. The browser mounts React Router, Auth Context, and TanStack Query. Pages handle workflow state and call domain API modules through a shared Axios client. The client attaches the in-memory access token, coordinates refresh, and limits automatic transport retries to safe methods. [Browser entry point](../frontend/src/main.tsx) · [Routes](../frontend/src/App.tsx) · [HTTP client](../frontend/src/api/client.ts)
3. FastAPI initializes settings, signing keys, request context, auth rate limiting, request auditing, and exception handlers. Routers validate request data with Pydantic, resolve the actor and database session, and call domain services. Services enforce workflow rules and control transaction boundaries. Repositories and direct SQLAlchemy queries in services provide persistence. [Application factory](../backend/app/main.py) · [API dependencies](../backend/app/api/dependencies.py) · [Async session](../backend/app/database.py)
4. PostgreSQL stores application state, audit and operational events, idempotency keys, and the report task outbox. Object storage holds media, documents, exports, and backups. Separate internal and public S3 client settings let services write through the private endpoint and generate URLs for the public proxy. [Schema index](schema/README.md) · [Storage client](../backend/app/services/storage_service.py) · [Production Compose](../docker-compose.prod.yml)
5. Redis supports authentication rate limiting and serves as the Celery broker and result backend. Celery workers handle scheduled jobs, imports, report export, and email. Beat schedules the task outbox dispatcher, database backups, workflow reminders, and maintenance in UTC. Those scheduled database backups are separate from the complete database-and-object recovery set and its required restore drill. Business-date validation uses the separately configured portal timezone. [Rate limiter](../backend/app/middleware/rate_limit.py) · [Task schedule](../backend/app/tasks/celery_app.py) · [Settings](../backend/app/config.py)

Portal email can use useSend or SMTP through `EmailService`. Login and password-reset codes send during the auth request. Notification and report email tasks record delivery state and retry transport failures. [Mail transport](../backend/app/services/email_service.py) · [Auth service](../backend/app/services/auth_service.py) · [Email tasks](../backend/app/tasks/email.py)

Analytics loads its chart bundle when the summary has chart data. The filter controls and project totals can render while the chart code downloads. [Analytics page](../frontend/src/pages/analytics/AnalyticsPage.tsx) · [Chart module](../frontend/src/pages/analytics/AnalyticsCharts.tsx)

## Workflow invariants

### Project setup and scheduling

- Managing Director and Operations Director can create a project with milestones and zero or more initial BOQ items. MEP Project Managers can create Planning projects, with or without an initial BOQ, but receive no downstream priced BOQ modification authority; Group Project Managers cannot create projects. Directors can add one priced BOQ item at a time from editable project details. The service locks the project, validates project-local item codes and milestone links, calculates amounts with Decimal, increments the project revision, and audits the addition in the same transaction. BOQ CSV/XLSX imports remain available to directors. Quantities and rates stay decimal-valued, and financial fields remain redacted without `financial:view`. [Project setup service](../backend/app/services/project_service.py) · [Project endpoints](../backend/app/api/v1/projects.py) · [Project form](../frontend/src/pages/projects/ProjectCreateForm.tsx) · [Project details](../frontend/src/pages/projects/ProjectDetailPanel.tsx)
- Project and task edit screens send the revision from the record they opened. The service serializes project edits, assignments, and task changes on the parent project. Existing project metadata and assignment API clients may omit the revision during transition. The task update endpoint requires it. A task keeps one predecessor in the same project, and the service rejects cycles. [Project endpoints](../backend/app/api/v1/projects.py) · [Timeline](../frontend/src/pages/projects/ProjectTimeline.tsx)

### Field reporting and offline recovery

- Senior Site Supervisors and Site Supervisors draft and submit their own updates for assigned projects, and can preview thumbnails or open/download uploaded draft files (with HEIC files marked original-only). Engineer report submission verifies selected updates from the same project and records who verified them. Official daily reports have their own draft, submission, and decision path. Report submission assigns the report number, and a rejection returns the report to draft with reviewer feedback. [Supervisor updates](../backend/app/services/reporting_service.py) · [Supervisor update screen](../frontend/src/pages/reports/SupervisorUpdatePage.tsx) · [Daily reports](../backend/app/services/report_service.py)
- Approval locks the report row before checking its state. It records the decision, consumes report materials, and writes a PDF task outbox entry within the transaction. The scheduled dispatcher publishes pending entries. The export task stores the PDF and can queue email to configured report recipients. [Report service](../backend/app/services/report_service.py) · [Outbox dispatcher](../backend/app/tasks/outbox.py) · [Report tasks](../backend/app/tasks/report.py)
- New official daily reports reject a date before the current business date. An edit to a numbered report can retain its original date, and resubmission keeps that report number. Supervisor update creation and edits reject dates before the previous business-calendar date. [Daily report dates](../backend/app/services/report_service.py) · [Supervisor update dates](../backend/app/services/reporting_service.py)
- The service worker caches the app shell. IndexedDB stores local daily report drafts and queued uploads. A queue flush persists the latest valid owned draft even without attachments. It records the server identity and revision before uploading files. An older local revision cannot overwrite a newer server report. The browser and service-worker fallback share the same grouping, claim, and retry behavior. [Offline queue](../frontend/src/api/offlineQueue.ts) · [Service worker](../frontend/public/sw.js)
- Queued report files use the same byte checks in the app and worker. A blocked file stays available for removal with its reason. The queue records the first expected report revision before sending. If the response is lost, a replay uses the same file key and expected revision, and an exact receipt advances the draft base and clears the queued copy together. [Queued upload rules](../frontend/public/report-file-sync.js)
- Offline draft and upload records are partitioned by the verified user and application/API origin. OTP verification checks that the browser can open the durable IndexedDB session store before consuming the one-time code, so an offline-storage upgrade blocked by an older tab does not burn the code; the sign-in screen also lets users request a new code after expiry. A session generation fences queued operations in the browser and worker. Sign-out clears the current user's local drafts and queued uploads after confirmation. Session expiry suspends sync and keeps the records for that user to resume after sign-in. [Offline storage](../frontend/src/api/offlineDb.ts) · [Browser session](../frontend/src/api/browserSession.ts) · [Sign-in screen](../frontend/src/pages/auth/LoginPage.tsx)
- Report creation and photo upload accept an optional `Idempotency-Key`. A PostgreSQL record scopes the key by user and route and binds it to the resource in the write transaction. Replays can recover the original resource after a dropped response. [Idempotency service](../backend/app/services/idempotency.py) · [Idempotency tests](../backend/tests/test_idempotency.py)

### Approvals, inventory, and finance

- The approvals screen separates daily report decisions, the workflow inbox, and the current user’s outbox, and both the approvals and daily-report screens load a focused `reportId` from the query string when it falls outside the initial page. Notification history renders same-origin workflow links to `/approvals`, `/reports/daily`, `/documents`, `/finance`, and `/materials` as in-app navigation links. A conflicting decision refreshes the record and its action controls. Entity-backed approvals are opened by their owning workflow. The generic approval service enforces request-specific delegation rules and an open-request uniqueness constraint. Pending decisions, reminders, and escalation are implemented there. [Approvals UI](../frontend/src/pages/approvals/ApprovalInboxPage.tsx) · [Notifications UI](../frontend/src/pages/notifications/NotificationsPage.tsx) · [Approval service](../backend/app/services/approval_service.py)
- Inventory records movements and maintains stock and reservation quantities by item and location. A receipt requires an active destination and a quantity representable to three decimal places. The stock forms retain the original request and key when the result is unconfirmed. Replaying that key returns the recorded movement. Material-request creation, reservation, issue and cancellation require `inventory:manage`. Selected quantities use the request revision and an idempotency key. Cancellation closes open approvals and releases unused reservations in the same transaction. [Inventory routes](../backend/app/api/v1/inventory.py) · [Inventory service](../backend/app/services/inventory_service.py)
- A tagged transfer moves one unit of the asset's item between two distinct active locations. The transfer locks the tag, checks its current location and available stock, then updates the tag and stock in the same transaction. [Inventory service](../backend/app/services/inventory_service.py)
- Finance grants reads to Managing Director and Operations Director. The budget summary compares the project budget with billable invoices and reports recorded payments separately. Invoice creation, correction, resubmission, status decisions, attachment uploads and payment writes run through finance services that reject mutations under the active role policy. The generic approval workflow also denies invoice decisions. [Finance service](../backend/app/services/finance_service.py) · [Approval service](../backend/app/services/approval_service.py)
- Finance exposes a minimal active-supplier lookup to authorized readers. Supplier managers control deactivation and TDS evidence, and the supplier register applies newer revisions to cached rows. Existing invoices and stock retain their historical supplier references. [Finance routes](../backend/app/api/v1/finance.py) · [Supplier service](../backend/app/services/supplier_service.py) · [Suppliers UI](../frontend/src/pages/suppliers/SuppliersPage.tsx)
- Analytics scopes an explicit project filter to users with project-read access to that project. Without a project filter, company-dashboard holders can see company aggregates. Material usage requires inventory viewing and uses category text. The project panel searches project scope text and applies the location filter. Activity dates filter report and movement activity. Progress and authorized invoice and payment totals are cumulative. [Analytics service](../backend/app/services/analytics_service.py) · [Analytics routes](../backend/app/api/v1/analytics.py)

### Files, documents, and imports

- Photo and attachment access follows the owning entity. Uploads validate the supported file type and size. JPEG and PNG photo uploads can produce watermarked and thumbnail variants, and HEIC is stored as an original. Uploads serialize on the report or update row to enforce the five-active-photo quota. The API checks access before generating a time-limited signed link. The current role policy blocks deleted-media listing and recovery at the service boundary. [Photo service](../backend/app/services/photo_service.py)
- Document uploads start a version awaiting approval. Approval locks the parent document, validates and activates the selected version, supersedes the previous active version, and updates the cached document list and detail immediately in the UI. Download link responses set `Cache-Control: no-store` after document scope checks. The library normalizes type filters, shows the matching document total, and provides **Refresh preview** to request a new five-minute link for the version already open and check access again. [Document routes](../backend/app/api/v1/documents.py) · [Document service](../backend/app/services/document_service.py) · [Document library](../frontend/src/pages/documents/DocumentsPage.tsx)
- Imports validate template rows and show a preview before execution. Background processing locks the existing batch and commits imported rows with the completion marker. Document imports create metadata, including the supplied filename. Use the document upload flow for binaries. [Import templates](import_templates/README.md) · [Import service](../backend/app/services/import_service.py) · [Import tasks](../backend/app/tasks/imports.py)

## Security and scoping

- Sign-in requires a password and an OTP. The browser uses a short-lived bearer JWT and a rotating HTTP-only refresh cookie. For authenticated requests the API reloads the active user, so current account state and role govern permissions. Password changes, resets, and administrative password updates revoke refresh sessions. Production requires configured RSA signing keys at startup. `JWT_ALGORITHM` selects one of `RS256`, `RS384`, or `RS512`. The verifier accepts only the selected algorithm and requires a subject and expiration. The application retains hardened staging compatibility settings, but staging is not an active deployment target. Production disables development OTP exposure and ignores the staging login code. [Auth API](../backend/app/api/v1/auth.py) · [Auth service](../backend/app/services/auth_service.py) · [Signing key validation](../backend/app/utils/security.py)
- Route dependencies check baseline permissions where declared. Services check scope, ownership, eligibility, and state. Browser route and menu gates control what the UI presents. Consult the [access guide](ROLES_AND_PERMISSIONS.md) when adding an operation or changing visibility.
- Nginx applies security headers and sets the forwarding headers used by the API. Client IP resolution trusts forwarding data according to configured proxy addresses. [Production Nginx configuration](../nginx/nginx.prod.conf) · [Request IP handling](../backend/app/utils/request.py)
- Audit rows and application-side operational events persist in PostgreSQL. API and worker logs also go to stdout for Alloy and Loki. Grafana queries Loki and can send alerts. The [observability diagram](../README.md#observability-and-audit) and [log guide](LOGGING_AND_REMOTE_CLI.md) explain both paths.
